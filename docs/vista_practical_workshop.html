VISTA Practical Workshop

Hands-on RNA-seq workflow using VISTA example data

Author

VISTA workshop

1 Learning Objectives

By the end of this practical you should be able to:

  • Load VISTA and its example RNA-seq data.
  • Inspect count data and sample metadata.
  • Prepare counts and metadata for VISTA.
  • Create and validate a VISTA object.
  • Understand where normalized expression, sample metadata, gene metadata, and DE results are stored.
  • Make QC, differential expression, and expression plots.
  • Run functional enrichment after checking DE results.
  • Export tables and plots.

5 3. Prepare Counts and Metadata

VISTA provides helper functions to standardize inputs before analysis.

prepared_counts <- read_vista_counts(
  count_data,
  format = "matrix",
  gene_id_column = "gene_id"
)
prepared_metadata <- read_vista_metadata(
  sample_metadata,
  sample_column = "sample_names"
)

Now match counts and metadata. This is one of the most important checks in RNA-seq analysis.

matched_inputs <- match_vista_inputs(

6 4. Create a VISTA Object

Now we run differential expression and create a VISTA object.

For beginners, focus on these arguments:

  • counts: the gene count table.
  • sample_info: the sample metadata.
  • column_geneid: the gene ID column.
  • group_column: the metadata column defining groups.
  • group_numerator: the group in the numerator of the fold change.
  • group_denominator: the reference group.
  • method: the differential expression backend.
vista <- create_vista(
  counts = matched_inputs$counts,
  sample_info = matched_inputs$sample_info,
  column_geneid = matched_inputs$column_geneid,
  group_column = "dex",
  group_numerator = "trt",
  group_denominator = "untrt",
  method = "deseq2",
  min_counts = 10,
  min_replicates = 2,
  log2fc_cutoff = 1,
  pval_cutoff = 0.05,
  p_value_type = "padj"
)

8 6. Why the VISTA Object Matters

A VISTA object keeps several parts of the analysis together:

  • normalized expression values,
  • sample metadata,
  • gene metadata,
  • differential expression results,
  • analysis cutoffs,
  • color settings and plotting information.

This follows the same logic as Bioconductor’s SummarizedExperiment: data and metadata should stay synchronized.

21 19. Exercises

Try these after the main workflow runs. Start with the easy questions, then move to moderate and hard questions if you have time.

21.1 Easy Questions

These questions focus on reading objects, changing simple arguments, and understanding the output.

  1. How many genes and samples are present in count_data?
  2. Which column in sample_metadata stores the sample names used by VISTA?
  3. How many samples are in each dex group?
  4. What is the name of the comparison stored in comp_name?
  5. How many genes are labelled Up, Down, and Other in de_table$regulation?
  6. Change label_n in the MA plot from 10 to 20. What changes in the plot?
  7. Make a PCA plot without sample labels by changing label = TRUE to label = FALSE.
  8. Change the point size in the PCA plot. Which value makes the plot easiest to read?
  9. Select the top 5 upregulated genes and print them.
  10. Select the top 5 downregulated genes and print them.

21.2 Moderate Questions

These questions require modifying code and interpreting the result.

  1. Create a barplot for the top 5 downregulated genes using get_expression_barplot().
  2. Create a boxplot for the top 5 upregulated genes using get_expression_boxplot().
  3. Change the expression heatmap so that it summarizes replicate groups instead of showing every sample.
  4. Make the expression heatmap using only the top 10 upregulated genes.
  5. Change the MA plot so that no genes are labelled. Which argument controls this?
  6. Run MSigDB enrichment for downregulated genes instead of upregulated genes.
  7. Make an enrichment plot for the downregulated MSigDB result.
  8. Export the DE result table using a new filename, such as vista_de_results_updated.csv.
  9. Save a PCA plot as a PNG file using save_vista_plot().
  10. Compare the PCA and MDS plots. Do the samples group in a similar way?

21.3 Hard Questions

These questions are designed for deeper thinking, troubleshooting, and extending the workflow.

  1. Change the differential expression cutoff in create_vista() from log2fc_cutoff = 1 to log2fc_cutoff = 0.5. How does the number of Up and Down genes change?
  2. Change pval_cutoff = 0.05 to pval_cutoff = 0.01. How does this affect the DEG summary?
  3. Re-run the workflow using method = "edger" instead of method = "deseq2". Are the top genes similar?
  4. Add cell as a covariate in create_vista() using covariates = c("cell"). How does this change the results?
  5. Try method = "both" and inspect the available DE result sources. What is the difference between using deseq2, edger, and consensus results?
  6. Use set_de_source() to switch the active DE source if you created a multi-method VISTA object.
  7. Run GO enrichment for downregulated genes and compare the top terms with the upregulated GO results.
  8. Use get_pathway_genes() to extract genes from the top enriched pathway. Then make an expression heatmap for those genes.
  9. Create a small report of your top biological interpretation: one sentence about the comparison, one sentence about the strongest DE genes, and one sentence about the top enriched pathway.
  10. Think about reproducibility: which files would you save or share so someone else can repeat your analysis?

22 20. Key Takeaways

  • Always inspect data before analysis.
  • Sample names in counts and metadata must match.
  • A VISTA object keeps expression, metadata, annotations, and results together.
  • QC plots should be checked before interpretation.
  • Functional analysis should be run after DE results and gene IDs are understood.
  • Exported tables and plots make the analysis easier to share and reproduce.
